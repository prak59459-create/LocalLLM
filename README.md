# LocalLLM

iPad の中だけで動く AI チャットアプリです。Hugging Face から Core ML 形式の言語モデルをダウンロードして、
インターネットに接続せずに会話できます。Swift Playgrounds（iPad）でそのまま開いて実行できます。

- 日本語 / 英語の UI
- Hugging Face のモデル検索とダウンロード（途中で止めても続きから再開）
- ストリーミング表示のチャット、会話履歴の保存
- 生成パラメータ（温度、top-p、top-k など）、システムプロンプト、思考モードの設定
- 速度（tok/s）とメモリ使用量の表示
- **マイアシスタント**: モデル・システムプロンプト・設定・参考資料（自分のコードや文書）をまとめた自分専用の AI（例: 自分のコードを知っているコーディング AI）
- **ミニLLM工房**: 小さな GPT を iPad の中でゼロから学習させて、文章の続きを書かせる
- **コーディングワークスペース（CDWS）**: エージェントと一緒にプロジェクトを作る。ファイルエクスプローラ、コードエディタ、プレビュー、
  機能が丸で並ぶロードマップのフリーボード、すべて元に戻せる変更履歴
- **コネクタ**: Web 検索（標準）・Web ページの取得・MCP サーバーのツールを、モデルが自分で呼び出す
- **分割モデル**: 1 つのパッケージになっていないモデル（ANEMLL 形式のチャンク、拡張子の無いフォルダ、ZIP）にも対応
- **アプリの更新**: このアプリの .swiftpm と GitHub を 1 ファイルずつ比べ、変わったファイルだけをダウンロードして書き換え、版を上げる（差分の確認・取り消し付き）
- **コンテキスト長の拡張**: ダウンロードしたモデルの最大コンテキスト長を、端末の中で最大 128k まで広げる
- 外部ライブラリなし（トークナイザ、チャットテンプレート、ダウンローダまで純 Swift で実装）

詳しい設計は [PLAN.md](PLAN.md) と [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) を見てください。

## 必要なもの

- iPadOS 18 以降の iPad（RAM 4GB 以上。小さいモデルから試すのがおすすめ）
- [Swift Playgrounds](https://apps.apple.com/app/swift-playgrounds/id908519492)（最新版）
- モデル用の空き容量（300MB〜2GB 程度）

## iPad で開く手順

1. iPad の Safari でこのリポジトリを開き、**Code → Download ZIP** でダウンロードします。
2. **ファイル** アプリで、ダウンロードした zip をタップして展開します。
3. 展開したフォルダの中の **`LocalLLM.swiftpm`** をタップすると、Swift Playgrounds で開きます。
4. 右上の ▶︎（実行）ボタンを押すとアプリが起動します。
   - 「アプリ」ボタンから自分の iPad のホーム画面に追加することもできます。

## 使い方

1. 左下の **モデル** → **おすすめ** から、まず **Qwen2.5 0.5B Instruct (4bit)**（約 290MB）を選んで **ダウンロード** します。
2. ダウンロードが終わったら **使う** をタップします（初回の読み込みは少し時間がかかります）。
3. 左上の **新しいチャット** を押して話しかけます。

### 自分専用のコーディング AI を作る

1. 左下の **アシスタント** → ひな形の **コーディング先生** を選びます。
2. 「使うモデル」に **Qwen2.5 Coder 1.5B** などを選びます（先にモデル画面でダウンロードしておきます）。
3. **ファイルやフォルダを追加** から、自分の Swift Playgrounds のプロジェクトフォルダなどを取り込みます。
4. **このアシスタントで新しいチャット** を押して質問すると、関係するコードを探して、それを踏まえて答えます。

### コーディングワークスペース（CDWS）

1. 左下の **コーディング** を開き、**新しいプロジェクト**（Web アプリ・iPad アプリ・JavaScript など）を作るか、**フォルダを開く** で
   iCloud Drive などのフォルダをそのまま開きます（Swift Playgrounds の `.swiftpm` も開けます）。
2. 右の **エージェント** に「ToDo リストを作って」のように頼むと、ファイルを読んで、書いて、直します。
   ファイルを変える前には差分つきで確認が出ます（メニューで「編集は自動で許可」にもできます）。
3. 上の **ロードマップ** では、作った機能や案が丸で並び、線でつながります。
   - 丸をドラッグで移動、背景をドラッグで移動、ピンチで拡大縮小、ダブルタップで丸を追加
   - 丸を選んで **ここから案を生やす** / **AI にアイデアを出してもらう** / **AI に実装してもらう**
   - **AI に計画** で、目標から機能の丸を一気に作れます
4. **プレビュー** で Web アプリを動かし、コンソールで console.log を見られます。`.js` は「実行」でそのまま動かせます。
5. **変更履歴** では、エージェントと自分の変更の差分を見て、1 つずつ、または依頼ごとに元に戻せます。
6. プロジェクトのメモを `CDWS.md` に書いておくと、エージェントが毎回読みます。

小さなモデルでも動くように、エージェントはファイルを少しずつ読んで直します。おすすめの **コーディング専用** のモデル
（Qwen2.5 Coder など）が向いています。

- **軽さ**: 標準で渡すツールは `read_file`・`write_file`・`edit_file`・`search_files`（空なら一覧）・`roadmap` の 5 つだけです。
  説明も結果も短くしてあり、古いツールの結果や書いたファイルの中身は自動で短くしてから渡すので、コンテキストがすぐには埋まりません。
- **画面**: 1 回の返答で使ったツールは「作業の帯」1 行にまとめて表示します（札をタップすると結果）。
  下の帯に、モデル・コンテキストの使い方・メモリの残りが出ます。

### Web 検索と MCP（コネクタ）

- 入力欄の左の 🌐 をオンにすると、送る前に Web を検索して、結果をもとに答えます。
- 🔧（ツール）をオンにすると、モデルが必要なときに自分で `web_search` / `fetch_page` / `current_time` を呼びます。
- **設定 → コネクタ** で、検索サービス（DuckDuckGo・Wikipedia・Brave・SearXNG）を選んだり、
  Streamable HTTP の **MCP サーバー** を追加してそのツールを使わせたりできます。

### 分割モデル・ZIP のモデル

検索画面の「探す場所」で **ANEMLL（分割モデル）** を選ぶと、埋め込み・本体のチャンク・出力層に分かれたモデルを探せます。
`meta.yaml` があればそれに従って部品をつなぎ、Neural Engine で動かします。ZIP に入ったモデルはダウンロード後に展開して調べます。

- **自動で 1 つにまとめる**: 部品ごとに ZIP（`X.mlmodelc.zip`）になっていても 1 つのモデルとして扱い、ダウンロード後にそれぞれ展開してつなぎます。
  大きなファイルが何個かに分けて置かれていても（`weight.bin.part1`…、`model.zip.001`…、`-00001-of-00003`）、つなげて 1 つに戻します。
- **tokenizer.json が無いモデル**: `tokenizer.model`（SentencePiece）・`vocab.json` + `merges.txt`・tiktoken 形式から、
  端末で同じ内容の tokenizer.json を作ります。どれも無ければ、元のモデル（base_model）や同じ系列のモデルから自動で取ってきます。

### コンテキスト長を広げる

1. **モデル → インストール済み** で、モデルの **コンテキスト長…** を押します。
2. 今の長さ・KV キャッシュの大きさ・学習時の長さが表示されます。2k〜128k から選ぶと、必要なメモリとこの iPad に収まるかが分かります。
3. **〜トークンにする** を押すと、モデルの中の「形」の情報だけを書き換えて（重みはそのまま）、Core ML で読み込めるか確かめます。だめなら自動で元に戻ります。
4. いつでも **元の長さに戻す** で戻せます。設定の **コンテキストの上限** で、使う長さをあえて短くすることもできます。

学習時の長さ（Qwen2.5 なら 32k）を超えると文章の質が落ちることがあり、長くするほど KV キャッシュのメモリが増えます（Qwen2.5 0.5B で 128k なら約 1.5GB）。

### アプリを更新する

GitHub のファイルとこの iPad の `.swiftpm` を 1 つずつ比べ、**変わったファイルだけ**をダウンロードして書き換えます（同じファイルには触りません）。

1. **設定 → アプリの更新** で、Swift Playgrounds のこのアプリ（例: iCloud Drive › Playgrounds › `LocalLLM.swiftpm`）を一度選びます。
   `.swiftpm` がうまく選べないときは、**Playgrounds フォルダ**を開いて「開く」を押すと、中のアプリの一覧から選べます。
2. **更新を確認する** を押すと、ブランチの最新のコミットのファイル一覧（git の識別子つき）を取り、この iPad のファイルの識別子と比べます。
   違うファイルだけをダウンロードし、中身が GitHub の一覧と同じか確かめます。
3. 追加・変更・削除されるファイル、前回の更新からのコミット、新しい版を確かめます。行をタップすると差分を見られ、チェックを外したファイルは書き換えません。
   この iPad でだけ書き換えたファイル（GitHub は前回から変わっていないもの）は、初めはチェックされていません。
4. **選んだ N 個のファイルを更新する** を押すと、選んだファイルだけを書き換えて版（displayVersion と bundleVersion）を上げます。
   `Package.swift` は、チーム・バンドル ID・アイコンなどこの iPad の設定を残したまま書き換えます。書き換えたファイルは GitHub と同じ中身か確かめ、
   途中で失敗したら元に戻します。
5. Swift Playgrounds でプロジェクトを開き直して ▶︎ を押すと新しい版が動きます。**更新の履歴**から、新しい更新から順に取り消せます。

起動したときに新しいコミットがあるかを軽く確かめ、あれば設定の「アプリの更新」に **新しい版** と出ます（オフにもできます）。
非公開のリポジトリはトークンを入れると使えます。GitHub の「Download ZIP」や別の `.swiftpm` とも、同じやり方で比べられます。

### LLM をゼロから学習する（ミニLLM工房）

1. 左下の **ミニLLM工房** を開きます。
2. 学習データを選びます（サンプルの「吾輩は猫である」、Tiny Shakespeare、自分のファイルなど）。
3. 大きさ（まずは **極小**）を選んで **学習を始める** を押すと、損失のグラフと「いまのモデルが書いた文章」が更新されていきます。
4. 終わったら名前を付けて保存し、保存したモデルに文章の続きを書かせてみましょう。

## 困ったとき

- **メモリ不足**: 生成の 1 回ごとに残りのメモリと減り方を確かめ、少なくなったら計算を小さく区切ります。
  次の 1 回で危なくなりそうなら、アプリが落ちる前に止めて、メモリを空け（必要ならモデルを読み直し）、古いやり取りを省いて
  自動で読み直し、続きから書きます。それでも足りないときだけ「メモリ不足で停止」と表示します。もう一度送ると、やり取りを短くして続けます。
  毎回会話全体を入力する形式のモデルは、今の空きで扱える長さまでに抑えます。それでも止まるときは、小さいモデルを使うか、
  他のアプリを閉じるか、モデルの詳細でコンテキスト長を短くしてください。
- **ダウンロードが止まった**: モデル画面の **再開** を押すと続きからダウンロードします。
- **ゲート付きモデル**: Hugging Face で利用規約に同意したうえで、設定に Hugging Face のトークンを入力してください。

## 開発者向け

Core（Apple 専用フレームワークに依存しない部分）は Mac / Linux でテストできます。

```sh
./Tools/fetch_fixtures.sh                # テスト用の tokenizer.json などを取得
pip install tokenizers jinja2 transformers
for f in Tools/fixtures/*.py; do python -I "$f"; done   # Python の参照実装で期待値を生成
swift test
```

GitHub Actions では、Linux で Core のテスト、macOS で Accelerate / Compression を使う部分のテストと、
iOS SDK に対するアプリ全体の型チェック（Swift Playgrounds の最適化なしビルドで遅くならないよう、型チェックの遅い式も検出）を実行します。
